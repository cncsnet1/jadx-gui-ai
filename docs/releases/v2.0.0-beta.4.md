# JADX GUI AI v2.0.0-beta.4

这次预发布将 APK 分析入口改为“应用调查”：先自动梳理接口、应用入口和有用材料，再让 AI 结合源码解释值得先尝试的方向。无需先知道类名，也不用先填写漏洞评级。

## 应用调查与路径探索

- 打开文件后默认进入应用调查；本机收集字节码和资源线索，无需连接模型。完成扫描后收起设置，将空间留给结果。
- 默认“找路径”视图按接口、入口、身份流程、密钥与数据、执行路径和配置组织起点，提供已有证据、建议追踪顺序和下一阶段材料。
- 可以导出单条线索包，带到抓包、设备或后端测试环境继续调查；建议路线表示搜索顺序，不代表已经还原的攻击链。
- 扫描在后台执行，支持进度、取消、同文件结果复用和项目保存。原有源码助手、AI 搜索和双向 MCP 继续保留。

## API 清单

- 分别展示 Retrofit 接口声明、地址线索，以及 OkHttp / HttpURLConnection 请求构造入口。
- 整理请求方法、路径、参数、请求体与认证线索，支持搜索、筛选、源码跳转及 JSON / Markdown 导出。
- 相对路径未关联基础地址、认证来源不明等情况会明确标记，不自动拼接无关域名、凭据或请求。

## AI 筛选优先入口

- “优先尝试”卡片比较本轮已读候选的进入条件、验证成本、已有防护和可能影响，给出排序理由、缺失证据、可能反证及下一步。
- 按“优先尝试 / 先补证据 / 条件较多”组织结果；纯地址、抽象签名、未知条件、已有防护或截断代码会受到保守的优先级限制。
- 每张卡只能引用为该线索实际收集的来源；错误编号、跨线索引用和原文不匹配会被排除。引用可跳回源码或证据快照。
- 修复抽象接口的方法提取可能返回空片段的问题，保留真实声明，并区分接口签名与行为代码。
- 卡片随项目保存，完整报告保留排序依据、原文引用和模型响应；响应格式错误或被截断时保留原始回答。

## 可选的人工核查

- “做核查”视图支持独立记录人工状态、影响评级与依据；AI 回答不会覆盖人工笔记。
- 同一文件中仍存在且证据身份一致的条目，在重新扫描后保留记录。文件变化、任务取消和项目切换有独立的结果隔离。

## 使用与边界

1. 完整解压新包，打开 APK、DEX、JAR 或 CLASS。
2. 在“应用调查”点击开始；未连接模型也可使用本地发现、API 清单和路线指南。
3. 配置自己的 AI 连接后，点击“AI 筛选优先入口”，或选中一条线索继续追查。

候选目录最多 60 项，单轮最多选择 6 条线索，上下文最多 16 份、36,000 字符；这不是完整攻击面扫描。敏感常量应用有限模式脱敏，人工笔记保存在本地，不自动加入 AI 请求。排序是基于已读范围的 AI 推断，不代表攻击成功率；客户端片段不能证明服务端存在授权缺陷。工具不会自动执行 APK、请求目标接口或验证凭据。

## 验证与发布包

- 本机发布构建通过：GUI 155 项通过、2 项跳过；Java 反混淆预处理 17 项通过、1 项跳过；内嵌归档回归 1 项及打包脚本 6 项通过。
- 验证源码引用归属、优先级限制、异常响应、项目保存与恢复、取消、卸载及人工记录隔离；深浅主题使用实际 Swing 组件与演示包验证。
- AI 交互自动化使用本机模拟服务验证流程，不代表真实模型的识别准确率。
- 六个平台包附带 SHA-256 与来源提交清单，校验 JAR 一致性、运行环境架构、启动入口、权限和文档完整性。
- Windows 包包含原生 EXE 与 Temurin 21 JRE；macOS / Linux 包进行归档校验，尚未在对应系统实机启动。Windows EXE 和 macOS 应用未签名，macOS 未公证。
- portable 包需自备 64 位 Java 17+；其余五个平台包内置运行环境。模型与外部 MCP 服务需自行提供。
