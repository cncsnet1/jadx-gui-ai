# v2.1.0-dev · 多技术栈路线与降噪预览

> 历史开发记录：相关功能已整理进入 [v2.1.0 正式版](v2.1.0.md)。下文保留当时的预览状态与验证范围。

本说明对应当前开发分支。本轮 Windows 构建仅为本地开发预览，尚未发布，不代表 v2.0.0 正式下载包已经包含这些改动。

## 打开后先做什么

拖入 APK 后，程序先在本地识别保护特征、技术栈和代码可见性，再按发现的技术栈检查对应产物。基础概览、API 梳理和自动路线不需要额外安装 Python、Node、APKiD、Frida 或 Ghidra，也不要求先配置模型。AI 使用已有模型连接，只有显式启动后才请求模型。

多个技术栈可以同时出现。概览可切换路线、查看覆盖状态、打开已有来源，或进入该路线的关键代码结果。没有可读业务代码时，界面保留产物盘点与解码缺口，不把文件存在当作分析成功。

| 路线 | 本轮自动分析范围 |
| --- | --- |
| uni-app | 配置、页面、可读脚本中的请求、认证存储、拦截器和桥接候选 |
| React Native | 可读 JS bundle 的请求、存储与桥接线索；Hermes 格式识别 |
| Cordova / WebView | 本地 HTML、JS、配置声明与桥接候选 |
| Flutter | 已打包的资源配置、Java 侧线索与相关 ELF 证据 |
| Android / Java / Kotlin | 复用本地接口、组件、加密调用及受限静态追踪 |
| Unity | managed、IL2CPP 和相关 native 产物盘点 |

## 先看到值得继续读的内容

- API 清单默认折叠背景候选，并说明归属线索、证据类型和分层原因。未知归属的接口声明和请求构造仍保留在默认视图；勾选「显示背景候选」可恢复，其他页面显式定位的背景接口也会展开。
- 折叠不删除记录，不改写 URL、token、请求头或参数值，全部 API 导出仍包含已保存的原始值。分层表示阅读顺序，不表示风险程度、漏洞成立或 SDK 归属已经确认。
- 大量资源匹配先占用一般预算时，应用与归属未知的字节码线索仍有额外、有上限的保留空间。预算耗尽后保留省略匹配计数与覆盖缺口，不把受限结果描述为完整扫描。
- 同一发现最多保留 5 份带原文的片段预览和 128 条精简来源索引。预览仍受长度限制，索引不重复保存完整代码；超限统计是来源出现次数，不是唯一遗漏位置数。

## 从一条线索继续追踪

显式选择线索后，AI 先读取该线索的来源与已追踪引用，围绕缺失环节再定向查找。背景候选仍能通过搜索和读取工具找到。源码中的实际值会保留在相关证据中；显式 AI 操作会把所选原文及后续读取的相关证据发送到已配置模型，人工评审备注不会自动发送。

这里的来源关联和受限追踪不等于完整程序切片、跨文件数据流或运行时可达性证明。恢复已有报告、切换路线和重新扫描不会自动启动模型。

## 能力边界

- 保护特征是有来源的静态线索；未命中不等于无壳，本轮没有自动脱壳。
- 未集成 Hermes 解码、Dart AOT 反编译、C# 恢复或 IL2CPP 映射解码；相关路线明确显示盘点状态和缺口。
- 未集成 FlowDroid、LibScout 或 TruffleHog 引擎；来源提示和规则评分不能当作库版本鉴定、完整污点传播或凭据有效性验证。
- 大资源、损坏文件、动态拼接和扫描预算仍可能限制覆盖。显示全部只能恢复已保存但被折叠的候选，不能恢复从未读取或收录的内容。
- 本说明不作为真实 APK、模型、设备或外部工具端到端验证的证明。当前预览与已发布安装包应分别验收。
