# Agent 任务工作台（v2.1.0）

本页描述 v2.1.0 正式版的 Agent 任务与证据恢复流程。

打开 APK 先获得本地报告，再把调查目标交给 Agent。选择「接口与认证」「登录与会话」「敏感信息用途」「可验证入口」，或直接写一句目标。已有模型连接可以继续使用，无需另装 Python、Node、Agent 框架或本地模型。

## 用户获得什么

- **可见的任务计划。** Agent 提出并更新最多六项工作，展示当前动作、读取次数与已保存证据。计划项是模型的调查安排；标记“已有证据”必须引用当前任务里真实存在的证据，并不等于漏洞已经验证。
- **自动推进取证。** Agent 可以读取代码、查找引用、追踪字节码调用、搜索扫描线索和类名、梳理 API 关系、读取资源与已保存证据。每次工具返回后，模型可以选择下一步；错误目标或重复读取会得到纠正反馈。
- **一句话继续。** 停止后可以输入“接着查这个接口的认证逻辑”再继续。补充方向、原始目标和证据都随工程保存；新方向重新规划，已完成读取不重复执行。每条补充最多 2000 字，每任务最多 12 条补充。
- **带依据的交付。** 结果沿用源码引用与调查入口卡片，区分已观察内容、推断和缺少的运行时材料。计划项可以直接打开关联证据；完整工具日志按需展开。

## 实现边界

`InvestigationService` 管理任务与预算，`AgentPlanner` 管理模型工具协议，`LocalAnalysisTools` 执行本地读取，`InvestigationRun` 保存计划、补充方向和证据。复用现有 Java 运行时、JADX 引擎、模型连接和项目保存流程。

模型支持函数调用时，直接使用七个读取工具及 `update_plan`、`finish_investigation`。第一条工具请求被端点以 400 / 404 / 422 / 501 拒绝时，自动尝试结构化 JSON 兼容方式；界面会标明兼容模式。鉴权、限流、服务器故障和已成功工作的工具会话不会被悄悄降级。兼容模型仍需遵循结构化输出，不能保证任意模型都能可靠执行。

每次开始或继续最多 **10 轮决策、12 次本地工具读取**；规划及完成控制调用占决策轮数。初始线索由本地准备，最终归纳另有模型请求。本地取证累计 60 秒预算在操作间检查；单次反编译不保证立即中断，模型请求使用原连接超时。连续两轮无新证据或两次无效请求停止并保存已有工作。

首次在本地从有限目录选择最多三项线索，并在模型请求前保存证据。每任务最多 96 份证据、384,000 字符、160 个步骤；最终回答最多使用 16 份、36,000 字符证据。搜索覆盖扫描线索与类名，并非全源码语义搜索。不能据此声称已全面审计 APK。

这个 Agent 的工具均为本地静态读取。Burp 实际流量工作台和外部 MCP 仍使用各自明确的入口；本轮没有把目标请求发送、设备执行或任意外部工具自动交给 Agent。模型服务配置仍需要用户自己的连接信息。旧项目记录可继续查看，只有输入和引擎配置匹配的任务才能继续。

## 响应被截断时

旧预览会先用 512 个输出 token 请求模型挑选线索；如果返回 `finish_reason=length`，尚未保存证据就结束。现已移除这次前置请求，本地证据先保存，再进入 Agent 决策。

工具决策、JSON 兼容决策和最终归纳均使用至少 4096 个输出 token；若明确收到 `length`，自动扩大至至少 16384、至多 32768，并重试一次。后续决策复用已扩大额度；鉴权、限流、网络错误不会触发这类重试，取消立即生效。扩大的是单次上限，实际计费仍取决于服务商和生成量。截断的工具请求不执行，半份结论不保存。重试仍失败时保留本地报告和已采集证据，界面给出原因及「用已有证据重试」入口。

按 [DeepSeek 思考模式工具协议](https://api-docs.deepseek.com/guides/thinking_mode/) 保留工具续接所需的 `reasoning_content`。该字段只在当前模型会话内原样回传，不作为用户可见计划，也不进入工程、报告或证据。工具参数仍单独校验大小、操作名和目标。

## 验证

回归覆盖启动前证据保留、响应截断恢复、重试耗尽、思考模式续接、原生工具结果回传、错误目标后的重新规划、无效计划不得执行读取、证据引用校验、兼容回退、鉴权和限流错误、补充方向保存与原值保留、旧记录迁移、取消与预算。Windows Swing 流程覆盖新建任务、计划、证据跳转、补充后继续、工程保存恢复、停止保留、项目卸载及深浅主题。

使用本机协议样本验证执行机制和界面；真实模型的调查质量依赖所选模型与实际 APK，尚不能把这些测试视为推理质量评测。

设计参考 [Anthropic 的 Building effective agents](https://www.anthropic.com/engineering/building-effective-agents)：围绕工具反馈迭代，保留清晰的停止条件和用户可见的工作进展。项目选择复用现有 Java 能力，避免新增用户环境依赖。
