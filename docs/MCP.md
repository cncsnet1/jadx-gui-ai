# MCP：让 JADX 与其他工具互相调用

> 本功能从 **v2.0.0-beta.3** 开始随发布包提供。

入口：**工具 → MCP 连接中心**，或代码助手标题栏的 **MCP**。命令面板也能搜索该入口。

## 两个方向

| 模式 | 调用方向 | 当前能力 |
| --- | --- | --- |
| 共享 JADX | 外部 MCP 客户端 → 已打开的 JADX 项目 | 本机 Streamable HTTP，只读查询当前项目 |
| 外部工具 | JADX → 你配置的 MCP 服务 | stdio 子进程或 Streamable HTTP；可手动执行，也可交给 AI 选择 |

服务端不需要配置模型或 API Key。AI 调用外部工具时，所选模型需要支持 OpenAI 兼容的 Chat Completions `tools` / `tool_calls`；普通源码分析仍使用原来的流式接口。

## 让其他 AI 调用 JADX

1. 打开 APK、DEX、JAR 或 class 文件，等待项目加载完成。
2. 在连接中心的「共享 JADX」页选择端口，点击「共享当前项目」。默认端口为 `8650`；设为 `0` 可自动分配。
3. 点击「复制客户端配置」，粘贴到可信 MCP 客户端中。客户端需支持 Streamable HTTP 与自定义请求头；各客户端的配置字段可能不同。

典型配置如下，**以界面实际生成的地址和令牌为准**：

```json
{
  "mcpServers": {
    "jadx": {
      "url": "http://127.0.0.1:8650/mcp",
      "headers": {
        "Authorization": "Bearer REPLACE_WITH_TEMPORARY_TOKEN"
      }
    }
  }
}
```

可向外部 AI 提问：“先列出当前项目的类，找到登录相关入口，读取对应方法并查询引用。”

| 工具 | 参数 | 用途 |
| --- | --- | --- |
| `get_project` | 无 | 输入文件名与类数量，不返回完整磁盘路径 |
| `list_classes` | `query`、`offset`、`limit` | 按名称子串搜索类，包含内部类 |
| `get_class_code` | `className`、`offset`、`limit` | 读取反编译源码 |
| `list_methods` | `className`、`offset`、`limit` | 获取方法名称与稳定的 `methodId` |
| `get_method_code` | `className`、`methodId`、`offset`、`limit` | 读取指定方法源码 |
| `find_usages` | `className`、可选 `methodId`、`offset`、`limit` | 查找类或方法的引用 |
| `search_code` | `query`、`offset` | 不区分大小写的字面源码搜索，每次扫描至多 20 个顶层类 |

v2.0.0 正式版新增两个共用本地操作：`trace_calls(className, methodId)` 返回最多 32 个直接字节码调用目标及覆盖边界；`inspect_api(className, methodId)` 读取 Retrofit 声明的客户端构建、基础地址、已注册拦截器及来源，并返回有界的上游调用路径 `callPath`（节点、字节码调用边、指令偏移和停止原因）。这些关系与 GUI 使用同一实现，不执行 HTTP 请求，也不证明运行时可达性。

`className` 优先使用类列表返回的原始名称；`methodId` 必须使用方法列表返回的完整标识，以区分重载方法。分页从 `offset: 0` 开始；响应带有 `nextOffset` 时继续请求。列表默认 100 条、最多 500 条；源码默认 20,000 字符、最多 40,000 字符，偏移量按 Java UTF-16 字符单元计算。`search_code` 即使没有匹配也可能返回下一页。

项目共享仅绑定 `127.0.0.1`，校验 Host、Origin 和随机 Bearer 令牌。开启共享即允许持有令牌的本机客户端读取当前项目，不再逐条弹窗。停止、关闭或切换项目会撤销共享；再次启动会生成新令牌，旧配置需要更新。不会远程打开其他文件、修改源码、执行 Shell 或把外部调用再转交给 AI。

## 让 JADX 调用外部 MCP

在「外部工具 → 连接配置」页新增连接、填写配置、保存后点击「连接 / 重新连接」。连接不会随项目或程序启动而自动运行；重新连接会结束旧连接，stdio 服务会重新启动。

### stdio

- **可执行文件**：MCP 服务的程序路径，例如本机 Python、Node 或已安装的服务程序。
- **启动参数**：JSON 字符串数组，例如 `["E:/my-mcp/server.py"]`。Windows 路径也可使用双反斜杠。
- **环境变量**：JSON 对象，将子进程变量名映射到已存在的本机环境变量名，例如 `{"API_TOKEN":"MY_SERVICE_TOKEN"}`。

启动使用独立的可执行文件和参数数组，不自动拼接 Shell。`.cmd`、`.bat` 或 Shell 脚本需要你显式配置相应解释器；如果使用解释器，应自行检查命令及引用规则。JADX 不会自动安装 MCP 服务或依赖。

子进程只继承 PATH、HOME、系统目录、临时目录等基本运行环境，以及你明确映射的变量；不会整包继承父进程中的 API 密钥。参数和路径会保存在本机设置中，因此不要把密钥放进参数。凭据应通过环境变量映射传递。

### HTTP

- **MCP 服务地址**：完整端点，例如 `https://your-service.example/mcp`。
- **Bearer 令牌环境变量名**：例如 `MY_MCP_TOKEN`；留空表示不发送 Authorization。

远程连接要求 HTTPS，本机可使用 HTTP。URL 不允许内嵌凭据、查询参数或片段；不会跟随重定向。密钥从 JADX 启动时继承的环境读取，修改环境后通常需要重启 JADX。

### 手动测试和 AI 调用

连接后自动进入「工具测试」页，显示服务的工具列表。选择工具可以查看参数定义，填写 JSON 对象后点击「执行所选工具」，结果会显示在连接中心，**不会自动发给模型**。

在代码助手的「上下文选项」中勾选「使用 MCP 工具」后，本次分析可以使用已连接服务中所选范围的工具。工具描述与参数定义会发给所选 AI 服务，可在「上下文」的完整请求中检查。模型提出工具调用时，会显示目标服务、工具名、参数和接收结果的 AI 服务；只有点击「允许本次调用」后才会执行。拒绝也会告知模型。取消分析会关闭待确认窗口。

调用结果是外部数据，不是指令；文本和结构化结果会被限定大小后交给模型，不会自动读取结果中的链接或加载媒体。回答末尾记录实际尝试的工具名与拒绝/错误状态。外部工具依据与源码 `[S1]` 引用应分别核对。

## 可选 REA 接入（v2.0.0）

连接配置新增「AI 工具范围」：`all` 使用服务公布的工具；`rea-static` 只选择 REA 会话、静态函数/调用路径、导航与证据读取工具。手动测试仍可查看完整目录。筛选使用实际工具名称和原始输入 schema，不猜测参数、不自动安装依赖、不自动启动 REA。每次外部调用继续使用原有授权流程。

先按 [REA 官方安装说明](https://github.com/morluto/rea/blob/ee87111009ace2ca4ef82c9aef09c82a37ca55f7/docs/installation.md) 准备本机服务，再配置其可执行文件与 `mcp` 参数；Windows 的脚本入口需显式指定解释器。可先手动调用实际目录中的 `binary_session` 核对会话和提供者。连接成功、目录存在不代表 Ghidra / Hopper / IDA 等引擎已可用。目录或模型上下文过大时会明确失败，不会删改参数 schema。

本轮用本地协议样本验证筛选和分页，未安装或运行真实 REA 原生分析引擎。应用报告的本地 APK 分析不依赖 REA；当前调查循环不会自动把本地证据交给外部工具，需在源码助手中明确启用 MCP。REA 自身返回的保留视图引用属于外部会话，重连后需重新检查。

## 兼容范围与限制

- 协议实现固定在 **2025-11-25**，协商兼容 `2025-06-18`、`2025-03-26`；stdio 客户端额外接受 `2024-11-05`。不声称实现后续修订。
- 本机服务端为无会话的 Streamable HTTP JSON 响应；GET/DELETE 返回 405，不提供独立 SSE 订阅流。
- 外部 HTTP 客户端支持 JSON/SSE 响应、初始化返回的会话 ID、版本请求头；工具目录需手动刷新。会话过期后需重新连接，不会自动重试可能产生副作用的调用。
- 当前实现 tools；不提供 resources、prompts、sampling、elicitation、OAuth、旧版 HTTP+SSE 或无 GUI 启动的服务模式。
- 每次外部请求最多 60 秒，消息限制约 1 MB；工具发现目录最多 1,024 个工具、累计 2,000,000 字符（单条传输消息仍限约 1 MB）。AI 目录保留最多 63 个外部工具、63,000 字符，并增加一个本地分页工具。
- 一次 AI 分析至多 4 轮工具调用、8 次执行（本地分页读取也计数）。短结果直接返回；超过 12,000 字符的文本/结构化结果在本次运行内完整保留，并返回有效 JSON 页封装。模型可用 `mcp_read_result` 和 `nextOffset` 每次读取最多 3,000 个 UTF-16 字符；分页不再调用外部服务。最多保留 8 份、合计 2,000,000 字符，超出明确提示请求更小结果。引用不跨运行保存。开启 MCP 时使用非流式工具对话，完成后显示回答。
- stdio 取消或超时会断开并终止子进程，之后需要手动重连。取消不能撤销外部服务已经执行的操作。
- 运行外部 MCP 程序会赋予它当前用户的操作系统权限；环境变量过滤不是沙箱。仅连接你信任的服务。

实现依据：[MCP 生命周期](https://modelcontextprotocol.io/specification/2025-11-25/basic/lifecycle)、[传输规范](https://modelcontextprotocol.io/specification/2025-11-25/basic/transports)、[工具规范](https://modelcontextprotocol.io/specification/2025-11-25/server/tools)。

开发验证使用本机 HTTP/SSE 模拟服务、真实 Java stdio 子进程和真实 class 反编译样本；不代表已逐个验证所有第三方 MCP 服务及模型供应商。
