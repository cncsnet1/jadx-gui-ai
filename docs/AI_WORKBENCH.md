# AI 工作台使用手册

[返回项目首页](../README.md)

## 连接与模型

从工作台“AI 设置”进入连接中心。每套连接独立保存名称、API 地址、认证方式、模型 ID 和输出上限，最多 20 套。旧版单套配置会自动作为“现有连接”载入。新增、复制、删除、默认连接和任务分配在“保存配置”后生效，取消保留原配置。

目前使用兼容 Chat Completions 的 HTTP(S) 接口。基础地址会自动补全 `/chat/completions`，也可以填写完整地址。“读取模型”使用同一服务的 `/models`，不支持时可以直接输入模型 ID。厂商原生协议需要兼容网关。

测试模型响应会发送一条简短消息，检查完整流式响应并显示耗时，不发送项目源码。验证结果只代表地址、认证和模型响应可用，不代表分析质量；修改配置后旧验证结果失效。请求均可停止。

任务分配允许解释、追踪、审计、命名分别选择连接。未指定时跟随默认连接，工作台可临时覆盖。请求失败会直接报错，不会自动改用其他服务。旧版 AI 搜索使用默认连接。

## 密钥与数据

- 直接填写的 API Key 沿用本地设置文件，以明文保存。
- 环境变量方式只保存变量名，在发送请求时读取应用进程中的值；变量缺失或为空会报错，不会回退到其他凭据。更改系统环境变量后通常需要重启应用。
- 主动分析会发送明确选择的源码快照、可选调用者和同一上下文下的近期对话。选择代码本身不会请求模型。
- 模型列表读取和连接测试不发送项目源码。调查台浏览与人工复核不调用模型。
- 项目记录与报告包含源码快照。模型来源记录包括连接名、模型和服务主机，不保存连接密钥。

## 选择上下文

打开 Java 类，把光标放在方法中，或选中一段代码。工作台使用当前编辑器已呈现的源码，必要时按需补充最多 3 个调用者。

| 内容 | 上限 |
| --- | --- |
| 主要源码 | 12,000 字符 |
| 调用者源码 | 最多 3 处，每处 3,000 字符 |
| 近期追问 | 最多 2 轮，消息合计最多 16,000 字符 |

截断会明确标识。“上下文”窗口展示证据快照与完整请求；打开不会联网，“发送这份快照”复用所显示的同一份消息。字符数不代表精确 Token 数。

切换服务、账号配置、模型、分析任务或源码上下文后，旧对话不会自动带入新分析。

## 分析与引用

选择解释、追踪、审计、命名，或者输入具体问题。流式分析可随时停止。切换项目会使旧请求失效，过期回调不能覆盖新项目的内容。

分析使用 45 秒空闲超时和 3 分钟总超时；未完成的响应不能作为完整分析保存。连接诊断使用更短的等待时间。

`[S1]` 等引用可跳回对应源码符号。引用基于分析时的快照，当前源码可能已经变化；不要把旧快照当作当前运行行为。

## 调查台与人工复核

解释、追踪、审计可请求最多 8 条结构化线索。每项属于源码观察、待证假设或开放问题，展示分析依据、缺失条件、可能的反证和建议验证步骤。

“源码证据”会按编号查找本次快照，再检查引用的连续文字是否精确匹配。匹配只证明该片段出现在快照中，不证明语义判断正确。引用缺失、编号不存在、文字不匹配均会显示提示。

模型给出的每条线索初始为“尚未复核”。你可以改为人工确认有依据、人工否定或仍需补充证据，并填写最多 4,000 字符的复核笔记。模型返回的复核字段不会替代人工状态。

切换线索会保留当前草稿，关闭或返回源码前会提示处理未保存修改。“保存复核到项目”会同时加入这份分析，重复保存不会新增重复记录。请保存 `.jadx` 项目以写入磁盘。

没有有效结构化输出时，保留完整文本，不会从不完整数据中伪造卡片。命名任务继续使用原有命名建议格式。

## 建议应用与导出

“预览注释”和“预览命名”打开原生编辑对话框，确认后应用。应用前检查原始符号身份与源码指纹，源码已经变化时需要重新分析。

每项目最多 100 条分析或固定源码记录。Markdown / HTML 报告包含模型来源、分析正文、结构化线索、人工复核与时间、引用核对结果、源码快照和模型原始响应。

## 当前边界

分析基于源码与有限静态调用上下文，不执行全 APK 数据流分析、自动漏洞验证或动态 Hook。当前调查台管理单次分析的线索；跨分析调查目标、多模型分歧复核和动态验证结果回填仍是后续方向。
