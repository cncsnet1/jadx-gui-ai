# AI 工作台使用手册

[返回项目首页](../README.md)

> v2.1.0 提供「应用概览 / 接口与通信 / 关键代码」、多技术栈自动路线及可恢复背景候选，详见 [APK 工作台](APK_WORKBENCH.md)。Agent 支持可见计划、原生工具调用、重新规划和补充方向后继续，沿用已有模型连接，详见 [Agent 工作台](AGENT_WORKSPACE.md)。

## 面向目标的自动分析

本节介绍 v2.1.0 正式版的应用调查流程。

打开 APK 后自动生成本地报告，不需要先配置模型或点击扫描。「应用概览 / 接口与通信 / 关键代码」是工作区的三个主页面；Agent 任务与历史证据按需打开；已打开项目时，左侧「开始」返回报告，「源码」进入原有文件树。首次扫描和恢复缓存均不发起模型请求。

应用概览先展示保护特征、技术栈、代码可见性、自动路线和少量值得看的线索，说明依据与未知条件，再提供「梳理请求与认证」「追查敏感信息的用途与去向」「寻找外部入口」。点击「全部线索」可以进入原有路线指南与人工核查队列，技术细节按需展开。路线指南不等于已证实的调用链或攻击链。人工记录规则见[应用调查说明](ASSESSMENT_WORKFLOW.md)。

基础扫描在本机执行，无需 Python、Node 或外部服务。它读取独立字节码 reader，扫描字符串常量、命名字段常量、Retrofit 注解、Manifest 和支持的文本资源，不为初步发现反编译全部类。发现与资源读取有上限，应用/未知归属字节码有额外保留预算；过大资源、方法与读取失败会列为覆盖缺口。关键词共现只是调查入口，没有发现也不能证明安全。

接口与通信支持按证据类型和域名、路径、方法、参数、位置搜索。「一键梳理接口」无需模型，会核对字节码并向上追查最多四层调用者，同时按需读取 Retrofit / OkHttp 的客户端构建，分别展示多个客户端的基础地址、注册拦截器和来源片段。只确认直线构建代码中的关系；分支、动态配置、辅助函数、注入和反射不能确定时明确留空。不会把相对地址与 APK 中任意域名拼接，也不会因没有发现认证头就判定匿名可用。调用树可查看逐条调用依据并跳转精确方法；循环和复用关系不会无限展开，达到预算或无法验证的地方保留追查边界。API JSON 导出包含请求关系与调用路径；Markdown 导出包含关系与来源。详见 [API 清单说明](API_INVENTORY.md)。

配置模型后，点击一个调查目标或线索开始 AI 调查。程序先在本地从有限目录准备最多 3 项起点并保存证据；显式选定线索时优先沿该来源与已追踪引用继续。模型随后使用限定的本地操作读取符号、查找引用、追踪直接调用、搜索已有线索与类名、读取 API 关系、资源与已保存证据。工具只能使用当前目录中的标识，不执行 APK、Shell、网络请求或账号尝试。每次开始/继续最多 10 轮工具规划、12 次工具读取；本地累计 60 秒预算在操作之间检查，单次反编译不保证立即中断。模型请求沿用连接超时。

「调查记录」保留每一步、证据快照、待解问题、停止原因和上次完整回答。「继续调查」沿用同一目标及证据，不重复读取已完成的操作。停止或请求失败后，已读取证据仍保留；不完整模型响应不会保存为新结论。界面注明上次回答对应的步骤，避免把旧回答误认为刚完成的新结论。无新证据、达到预算、等待材料与正常完成分开显示。

每项目最多 24 条调查，每条最多 96 份证据、384,000 字符、160 个步骤。最终回答上下文最多 16 份、36,000 字符；新增源码片段最多 6,000 字符，初始收集使用有界片段。模型只能看到有界范围，不能宣称已阅读整个 APK。静态证据与模型推断分开记录，优先尝试卡片仍需符合来源归属和引用核对规则。

工程保存包含报告、请求关系与调查记录。输入文件指纹、规则版本与引擎配置在后台校验；失配则重新进行本地扫描，原历史仅在相同输入时保留，配置不一致的调查不能直接继续。目录输入不复用缓存或跨加载继续。工程采用临时文件写入后替换，减少保存中断损坏原文件的风险。切换项目会取消旧任务并屏蔽过期回调。

v2.1.0 的字符串常量、私钥候选、URL 查询、参数与流量证据保留原值，受读取和展示长度上限约束，不作模式脱敏。原值可以进入保存的项目、报告和全部 API 导出。显式启动 AI 后，所选来源与后续读取的相关证据会发送到已配置模型。人工备注按原文保存在项目中，不自动发送给模型；连接认证密钥与供应商内部推理字段仍由各自的配置和日志规则处理。

当前不覆盖完整程序数据流、运行时解密、服务端行为或自动漏洞验证。完整图探索、运行时材料关联和 REA 原生证据导入仍属后续设计；当前 REA 扩展是 MCP 工具筛选与结果分页，见 [MCP 使用说明](MCP.md)。

## 连接与模型

从工作台“AI 设置”进入连接中心。每套连接独立保存名称、API 地址、认证方式、模型 ID 和输出上限，最多 20 套。旧版单套配置会自动作为“现有连接”载入。新增、复制、删除、默认连接和任务分配在“保存配置”后生效，取消保留原配置。

目前使用兼容 Chat Completions 的 HTTP(S) 接口。基础地址会自动补全 `/chat/completions`，也可以填写完整地址。“读取模型”使用同一服务的 `/models`，不支持时可以直接输入模型 ID。厂商原生协议需要兼容网关。

测试模型响应会发送一条简短消息，检查完整流式响应并显示耗时，不发送项目源码。验证结果只代表地址、认证和模型响应可用，不代表分析质量；修改配置后旧验证结果失效。请求均可停止。

任务分配允许解释、追踪、审计、命名、AI 搜索分别选择连接。未指定时跟随默认连接，工作台和搜索窗口均可临时覆盖。请求失败会直接报错，不会自动改用其他服务。

## 界面与主题

在“文件 → 首选项 → 外观 → 主题”中选择 **Jadx Graphite**（石墨灰）或 **Jadx Light**（浅色），两者以青绿色标记主要操作与选中状态，并配有同名的源码配色。新配置默认使用 Graphite；已有配置保留原主题。切换这两套主题时，基础编辑器配色 `default` / `dark` 和同名源码配色会同步匹配；其他编辑器配色保持原选择。

窗口采用左侧导航、顶部命令入口和中央工作区布局。首页集中展示打开文件、打开项目、最近项目与 AI 配置；左侧可切换首页、目标分析、源码、AI 搜索和代码助手，底部保留日志与设置入口。

按 `Ctrl + K`（macOS 为 `⌘ + K`）打开命令面板，输入菜单名称或功能关键词筛选命令，方向键选择、Enter 执行、Esc 关闭。命令复用原生菜单，保留禁用状态与快捷键，也包含当前插件菜单。原有菜单与快捷键仍然可用。

顶部“专注”临时收起文件导航和代码助手，点击“恢复布局”恢复原有面板及宽度。进入首页也会临时收起这些面板；返回代码后恢复之前的选择。首页与专注模式不会把隐藏面板的零宽度写入布局设置。

代码助手将“分析 / 引用源码 / 调查记录”并列展示。上下文选项收纳调用者、固定源码和 AI 搜索；模型选择与提问框放在底部。分析完成后，“…”菜单提供保存、导出、预览注释和预览命名。空白状态的示例问题只填入输入框，仍需点击发送才会请求模型。

## AI 搜索

打开项目后，点击左侧的“AI 搜索”，用自然语言描述想查找的功能。可以使用示例问题，也可以限定包范围或只搜索当前类及内部类。包范围按命名空间边界匹配，例如 `com.app` 不包含 `com.apple`。

搜索窗口在发送前显示候选类数、请求批次数、当前连接与目标主机。点击“查找相关类”或按 `Ctrl + Enter` 开始；不会在输入时自动请求模型。这里只发送问题与类名，不发送方法体、资源内容或工作台对话。

每批最多 160 个类名，并限制编码后的类名字符量；每批最多保留 20 个结果。结果逐批追加，模型返回的名字必须精确属于当前批次，重复与虚构类名会被丢弃。列表显示类名和包名，右侧显示匹配理由；双击结果或按 Enter 可以跳回代码。结果筛选仅在本地进行。

停止、出错后会保留已经完成的批次；再次搜索从当前范围重新开始。关闭搜索窗口或卸载项目会取消请求，旧回调无法覆盖新结果。当前类范围跟随编辑器选中的类，正在执行的搜索使用启动时的范围快照。

**搜索依据是类名的语义线索，并非源码行为分析。** 严重混淆的类名可能没有有效线索；匹配理由需要继续阅读源码核实。若模型未返回完整 JSON 结果，界面会报告解析失败，可以提高输出上限或切换模型重试。

## 密钥与数据

- 直接填写的 API Key 沿用本地设置文件，以明文保存。
- 环境变量方式只保存变量名，在发送请求时读取应用进程中的值；变量缺失或为空会报错，不会回退到其他凭据。更改系统环境变量后通常需要重启应用。
- 主动分析会发送明确选择的源码快照、可选调用者和同一上下文下的近期对话。选择代码本身不会请求模型。
- 模型列表读取和连接测试不发送项目源码。调查台浏览与人工复核不调用模型。
- 项目记录与报告包含源码快照。模型来源记录包括连接名、模型和服务主机，不保存连接密钥。

## 选择上下文

打开 Java 类，把光标放在方法中，或选中一段代码。工作台使用当前编辑器已呈现的源码，必要时按需补充最多 3 个调用者。

| 内容 | 上限 |
| --- | --- |
| 主要源码 | 12,000 字符 |
| 调用者源码 | 最多 3 处，每处 3,000 字符 |
| 近期追问 | 最多 2 轮，消息合计最多 16,000 字符 |

截断会明确标识。“上下文”窗口展示证据快照与完整请求；打开不会联网，“发送这份快照”复用所显示的同一份消息。字符数不代表精确 Token 数。

切换服务、账号配置、模型、分析任务或源码上下文后，旧对话不会自动带入新分析。

## 分析与引用

选择解释、追踪、审计、命名，或者输入具体问题。流式分析可随时停止。切换项目会使旧请求失效，过期回调不能覆盖新项目的内容。

分析使用 45 秒空闲超时和 3 分钟总超时；未完成的响应不能作为完整分析保存。连接诊断使用更短的等待时间。

`[S1]` 等引用可跳回对应源码符号。引用基于分析时的快照，当前源码可能已经变化；不要把旧快照当作当前运行行为。

## 调查台与人工复核

解释、追踪、审计可请求最多 8 条结构化线索。每项属于源码观察、待证假设或开放问题，展示分析依据、缺失条件、可能的反证和建议验证步骤。

“源码证据”会按编号查找本次快照，再检查引用的连续文字是否精确匹配。匹配只证明该片段出现在快照中，不证明语义判断正确。引用缺失、编号不存在、文字不匹配均会显示提示。

模型给出的每条线索初始为“尚未复核”。你可以改为人工确认有依据、人工否定或仍需补充证据，并填写最多 4,000 字符的复核笔记。模型返回的复核字段不会替代人工状态。

切换线索会保留当前草稿，关闭或返回源码前会提示处理未保存修改。“保存复核到项目”会同时加入这份分析，重复保存不会新增重复记录。请保存 `.jadx` 项目以写入磁盘。

没有有效结构化输出时，保留完整文本，不会从不完整数据中伪造卡片。命名任务继续使用原有命名建议格式。

## 建议应用与导出

“预览注释”和“预览命名”打开原生编辑对话框，确认后应用。应用前检查原始符号身份与源码指纹，源码已经变化时需要重新分析。

每项目最多 100 条分析或固定源码记录。Markdown / HTML 报告包含模型来源、分析正文、结构化线索、人工复核与时间、引用核对结果、源码快照和模型原始响应。

## 当前边界

分析基于静态观察和有限调用上下文，不执行全 APK 数据流分析、自动漏洞验证或动态 Hook。应用调查工作区负责本地发现、API 梳理、路线指南、AI 候选入口排序、有限的调用者追踪与可选的人工核查记录，调查台管理单次 AI 回答的人工复核；自动还原完整渗透链、多模型分歧复核、自动导入运行时证据和执行动态验证仍是后续方向。
